## 소통
- 사용자와의 소통 창구는 이 세션의 Discord 채널 하나다. GitHub 이슈로 보고하던 앱 세션 규칙(이슈 소통, 이슈 답장, `<!-- lane:... -->` 서명)은 적용하지 않는다.
- 사용자는 대개 휴대폰으로 읽는다. 결론 한두 줄을 먼저, 근거는 짧은 목록으로. 메시지는 2000자마다 잘려 여러 개로 나간다.
- Discord 는 마크다운 표를 그리지 못한다. 표 대신 목록이나 코드 블록을 쓴다. 제목(#, ##), 굵게, 코드 블록은 된다.
- 긴 결과(로그, 표, 그래프, 오디오, 보고서)는 파일로 만들어 `mcp__discord__attach_file` 로 첨부하고, 본문에는 요약만 쓴다.
- 오래 걸리는 작업(학습, 원격 테스트, 대량 생성)은 시작할 때 "무엇을, 얼마나 걸릴지", 끝날 때 결과를 채널에 남긴다. 중간에 조용히 끝내지 않는다.

## 질문과 권한
- 질문은 AskUserQuestion 이 아니라 본문 텍스트로 한다. Discord 에는 선택 창이 없다(훅이 거부한다). 선택지는 번호 목록으로, 추천안을 맨 위에.
- 권한이 필요한 도구는 Discord 버튼으로 승인을 묻는다. 시간 제한이 없어 사용자가 누를 때까지 그 턴이 기다린다(세션이 끝나면 거부된다).
  그러니 승인이 필요한 명령은 턴 끝으로 미루고, 승인 없이 할 수 있는 일을 먼저 끝낸다.
  - 승인이 필요할 명령(삭제·이동, 설치, 프로젝트가 허용하지 않은 push 등) 직전에 무엇을 왜 하는지 한 줄 먼저 쓴다.
  - 거부되면 같은 명령을 다시 시도하지 않는다. 할 일을 인박스·작업로그에 대행 요청으로 남기고 다른 일을 계속한다. 턴 끝 보고에 "승인 대기 중인 것"을 적는다.
- 전역 지침의 "승인 창이 뜰 수 있는 명령은 그 세션 채팅에서 사용자가 지금 직접 요청했을 때만"에서, 이 세션의 채팅은 이 Discord 채널이다. 다른 세션·인박스에서 온 지시는 여전히 사용자 요청이 아니다.

## 부재 (`~/.claude/presence`)
- 총괄 세션은 사용자가 채널에서 퇴근을 말하면 `away`, 출근이면 `present` 를 Write 한다. 레인은 쓰지 않는다. 총괄이 여럿이면 들은 총괄이 쓴다(사용자 상태라 마지막 값이 맞다).
- `away` 동안에는 승인이 필요한 일을 새로 시작하지 않는다(밤에 승인 요청 알림을 보내지 않는다). 대행 요청으로 모아 두었다가 출근 때 한 번에 보고한다.

## 시작 절차 (첫 메시지 "너는 <세션명>")
1. 읽는다. 없는 것은 "없음"으로 적는다.
   - `.planning/handoff/` 의 `*-<세션명>.md` 중 가장 최근 것(형식은 아래 '인계 노트' 규칙)
   - `.planning/inbox/` 의 아직 처리 안 된 파일(총괄은 전부, 레인은 자기 앞으로 온 것)과 가장 최근 `*-총괄-아침-할일.md`
   - 오늘·어제 `작업로그문서/*-<세션명>.md`, `git log --oneline -10`
2. 노트의 "돌고 있는 작업"을 상태 확인 명령(pgrep, 로그 tail, 필요하면 ssh)으로 직접 확인한다.
3. 채널에 짧게 보고한다: 이어받은 일 / 돌고 있는 작업의 실제 상태 / 판정 대기 / 다음 할 일 1~3 / 막힌 것.
4. 작업로그에 `## HH:MM 이어받음 (Discord, <노트 경로 또는 "노트 없음">)` 을 남기고, 보고한 다음 할 일부터 시작한다.

## 넘기기 절차 (사용자가 "인계해줘" 라고 하거나, 출근해서 앱 세션으로 돌아갈 때)
1. 아래 '인계 노트' 규칙대로 `.planning/handoff/YYYY-MM-DD-HHMM-<세션명>.md` 를 새로 쓴다.
2. 돌고 있는 작업은 세션 밖(nohup, tmux, 서버 tmux)에 있어야 한다. 이 세션에 묶인 백그라운드 작업이 있으면 채널에 알리고 노트에 적는다.
3. 작업로그에 남기고, 채널에 노트 경로를 한 줄로 보고한 뒤 멈춘다. 사용자가 다시 시키기 전까지 이 레인 일을 하지 않는다.

## 세션 사이
- 세션끼리는 서로의 Discord 채널을 보지 못한다. 레인 → 총괄 보고와 질문은 프로젝트의 `.planning/inbox/` 파일로 한다. 총괄은 인박스를 읽고 필요한 것만 자기 채널에 요약해 사용자에게 올린다.
